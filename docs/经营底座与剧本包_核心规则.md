# 经营底座＋剧本包：核心规则

状态：2026-11-06按用户最新要求形成的开发规则基线。本文件规定后续经营玩法的方向，不表示其中所有机制已经写入当前程序。当前0.7.0明末首片保留为交互、来源和存档验证原型；原型中的四省、四臣、三类事务和固定公式不能成为最终底座边界。既有冒险正式安装不受本次规则整理影响。

供模型按职责使用的纯规则另见[经营AI规则正文](history/经营AI规则正文.md)。它与开发说明分离，目前尚未接入运行时。

## 一、产品结构与主循环

模拟经营也是**通用底座＋剧本包**。明末、三国属于经营剧本；紫川仍为低武冒险。两种玩法共用TA的模型配置、语言、主题和通用基础设施，分别拥有游戏状态、时间和存档。

核心循环固定为：

**阅读当前局势／季度奏报 → 可选地找大臣讨论，或直接下诏 → AI依据全局局势推演本季 → 核定并保存实际结果 → 形成季度奏报 → 玩家调整、撤销或继续原有命令。**

季度推进由玩家主动发起，世界自主行动在该批次内推演；暂停或关闭游戏不按现实时间额外推进季度。

讨论和润色都是可选入口，不是直接下诏的前置条件。玩家可以只问意见而不行动，也可以明确委任大臣酌办。普通对话、表情和情绪自然展开，不逐句审批；需要跨季承接的承诺和关系变化由正常保存链留下来源，涉及钱粮、任免和政策的实际结果才走对应的正式处理。没有新诏令也可以进入下一季：有效政策、在办事务、其他势力和环境仍继续变化。

底座的主要工作是保证事实、命令、时间、来源、知情范围和保存一致；AI负责理解命令、人物决策、全局因果与结果推演。具体世界规则优先写进剧本与AI规则，只为必要的正式状态、校验和持久化补代码，不按每种政务不断新增关键词分支。

## 三、底座、剧本与本局的职责

| 层次 | 负责什么 |
| --- | --- |
| 通用经营底座 | 剧本加载与版本绑定；稳定人物、地区、机构、资源和命令身份；议事／下令／推演／奏报流程；来源、知情、记忆；资源账目一致性；存档、回溯、取消、重试与整季提交；通用前端呈现。 |
| 剧本包 | 世界与日历、玩家身份和权力范围、地区与运输、人物和关系、官制与机构、势力和社会群体、经济资源及计量、军政技术与时代边界、初始局势、事件压力、目标与结局、信息传播方式、文字和显示名称。 |
| 本局正式状态 | 这次游戏实际发生的事实、现任官员、当前资源、各方行动、有效命令与政策、在办事项、事件阶段、送达情报、关系、承诺及历史。模型提案和讨论不直接成为这里的结果。 |

底座以少量通用事实类型表达资源账户、人物/机构关系、命令状态和事件阶段，模型不能任意改未知字段；具体资源、制度和政策内容由剧本定义。

底座不写死1627、某位大臣、陕西、固定税率、固定例支、银两、内帑或某三种行动。剧本也不携带私人模型密钥、用户存档，不能覆盖底座的保存和信息隔离约束。

开局绑定剧本ID、版本和内容摘要，并保存所需规则与开局快照。作者后来改包不能悄悄改变旧档的世界；升级旧档需明确迁移并有恢复途径。新生成的人物、机构或政策先成为有来源的本局正式事实，不能只在正文中突然存在并接管事务。

同一底座应能载入明末和三国而不改通用程序。两包可以共用规则主题，但各自的官制、资源单位、政治结构、技术和事件不能互串。

## 四、议事、建议与正式命令

1. **议事**是询问、质询、比较方案和明确授权。大臣依据自己的立场、能力、利益与掌握的信息表达意见，可以有异议、偏好和误判；不能所有人都迎合玩家或说同一种话。
2. **建议**有提出者、当时局势、来源谈话和假设。玩家可采纳、部分采纳、修改或放弃；建议被保存不代表已经执行。
3. **拟诏**理解完整意图，保留所有子项、先后、条件、范围、授权和资源边界。来源可指向议事、奏报、旧命令或调查。不能只复制玩家的提问而丢掉大臣建议。
4. **正式颁令**以玩家明确发布／确认作为生效入口。直接输入的明确命令不必强制找大臣或先润色；确认要帮助玩家看清重大投入、冲突和取舍，不能变成逐字段审批表。
5. 对“由户部酌办，限额内处理”等委任，允许AI依据现行制度在授权内拟办。缺少固定预算、工期字段不自动等于不支持。只有会改变目标、重大资源或政治承诺的歧义需要澄清；不得借委任擅自突破限额或挪用独立账户。
6. 可执行建议应使用本局已有的人物、机构和时代能力；必要的新设机构或任命应作为待批准事项明确提出。讨论可以有前瞻想法，但不能把尚不存在的能力伪装成当前已经能执行的方案。

军事、内政、外交等可以用于整理输入和结果，不是底座永久写死的动作白名单。新政策优先由剧本规则、授权和正式事实结构表达，不能只因不属于旧有三个工程类型就被拒绝。

## 五、命令的持续、修订与撤销

一条正式命令拥有稳定身份和有效版本，至少能说明：谁下令、依据什么、目标和对象、责任人或机构、授权及资源边界、生效时间、条件、终止要求、实际状态。原文和修改历史保留。

| 命令性质／操作 | 必须遵守的语义 |
| --- | --- |
| 一次性命令 | 完成或确定失败后结束，不在每季重复扣款或重复发放成果。 |
| 跨季事务 | 保留阶段、投入、剩余资源、瓶颈、责任与已发生后果，逐季推进；不能每季重新创建一项。 |
| 持续政策／制度 | 没有“工程完工”这一必要终点；在授权和有效期内持续影响世界，直到到期、撤销、替代或失去适用条件。 |
| 条件命令 | 区分条件未成立、已成立待执行、实际执行。条件满足不等于效果已发生；执行次序和资源仍需统一推演。 |
| 继续 | 将原有效命令继续送入下一季；保持其身份、版本和已发生结果，不再扣一次总预算。玩家没重新抄写，命令也不因此消失。 |
| 修订 | 在原命令上形成新版本，只改明确改变的部分；未改的目标和边界继续有效，既有成果、成本、责任不清零。 |
| 暂停／恢复 | 保留未完事项和必要维护、停工代价，明确恢复条件；暂停不等于撤销。 |
| 撤销／替代 | 从明确时点停止未来效力。已花资源、政治信用、军情和社会后果保留；未用专款的退回与善后按剧本财政规则处理。 |
| 回溯存档 | 玩家在存档层恢复旧局势，属于另一种操作，不能用来冒充君主撤销政策。 |

总预算、每季投入和支出上限必须分清。例如一项总额12万的三季工程不会每季再收12万；每季2万、持续四季的政策则按其有效季度持续计支。未授权的资金来源不能因原预算不足而自动生成。

新命令明确修订或替代旧令时，保存关系与生效顺序；只是追加不同事项时，旧政策继续。两条命令争夺同一资源或目标冲突，需按玩家优先级和制度统一处理；重大歧义应在推进前说明，不能任取一句、把整段都标成成功。

## 六、AI全局推演的输入和责任

每个季度的推演必须使用同一个季初权威状态，而不是各部门各算一份互不相干的世界。现行视图至少包含：

- 剧本规则、时代技术、制度与权限。
- 国内外地区、政权、军队、机构、社会群体、人物、资源与关系的当前状况。
- 本季新命令、全部有效旧政策、进行中事务、待触发条件及未了责任。
- 已发生的重要因果、承诺、外交关系、持续危机、事件阶段和本季时间范围。
- 其他主体的利益、目标、已知条件与自主行动可能；玩家没下令的世界仍会变化。

“全局”不是无限塞入原始聊天。世界现状、有效政令、未了任务和危机必须留在现行视图；相关历史以有来源的摘要和检索补充。容量不足时分层整理或分阶段推演，不能悄悄删掉有效命令。摘要不是唯一事实源，完整正式记录仍能重建。

AI承担完整命令理解、人物与势力选择、执行偏差、国内外联动、事件发展、间接影响及未预期后果。它要考虑钱粮、人力、运输、官员精力和权力阻力的共同竞争，不能让每条命令都独占同一份资源。结果可以成功、部分成功、迟延、受阻、失败或产生代价，均须有局势和因果依据。

不为戏剧性每季重造无关灾难，不让一段豪言自动得到全盘成功。历史走向是剧本的背景压力与可能性；只有包中明确约定的不可干预事件才按该规则处理，不能无视玩家干预强行回到既定结局。

程序不应预先算完所有政策效果，再让AI只写奏报。程序负责稳定引用、资源与权限约束、规则版本、变化格式及提交一致性；AI对具体局势作出的候选变化，经这些约束核定后才成为事实。需要精确结算的数额有账目来源，不能只凭正文生效。

## 七、一季度怎样成为正式结果

逻辑上的一季可以包含多次模型调用，职责必须清楚：

1. **锁定本季输入版本**：汇总新命令、仍有效政策、进行中事务与全局局势，明确本季时间区间。日历年份、季节与开局第几轮由剧本分别解释，不能把轮次直接当公历季度。
2. **AI整体推演候选结果**：说明各项执行、世界反应、资源来源和去向、事件变化、未了事项及其因果。复杂局势可分角色或阶段讨论，但不能各自提交一份彼此矛盾的世界。
3. **核对统一候选状态**：引用的身份须存在或有明确创建过程；资源流量能对账，不能重复消费；执行顺序、权限与条件成立。错误交回修正或明确失败，不猜出财务动作。
4. **一次正式提交**：本季变化、命令/政策状态、事件、知情送达及新季状态保持同一个版本。核心推演失败或取消时不留下半季；重试同一次提交不再推进或扣费。
5. **生成并保存奏报**：依据已经核定的结果形成正文与明细，不能再改数、再发奖励或另算一季。可把正文生成与结果核定放在同一待提交批次；若文字生成单独重试，只重写表达，不重跑世界。

批次冻结后，新的正式修订不能悄悄混进本季旧输入。推演期间可以准备下季草稿；若玩家要求修订影响当前正在推演的一季，先取消尚未提交批次，再按新决定重新冻结和推演。并行页面或其他写入使输入版本失效时，拒绝提交旧候选并读取最新决定；不能覆盖较新的命令。已经提交后，新修订属于新季，取消也不能冒称已回退本季。

默认在待提交批次内准备好关键结果及面向玩家的结果摘要，再整体确认。若采用先结算、后补自然语言奏报，正文失败或取消必须明确显示“季度已结算，奏报待补”；重试只补正文，不能再推进或提示整季未发生。

季初状态、变化和季末状态必须明确分开。同一奏报不能同时把旧账当“当前”、又从别处拿新账。关键系统失败不能吞掉错误继续跨季。报告文案不是第二个结算引擎。

## 八、大臣记忆、局势与信息差

大臣每次发言的依据为：稳定身份与立场、当季应知信息、本人经办事务、未了承诺、相关个人经历、最近谈话。应知信息按职责和送达更新；不能只把新奏报放在玩家页面，让负责官员继续拿旧账回答。

长期命令从正式政策台账读取，不靠大臣聊天摘要“努力记住”。历史发言保留当时日期和来源，旧数不能覆盖本季已核定数据。人物记住承诺不等于承诺已经兑现；需要引用实际执行记录。

全局推演者、玩家和不同人物拥有不同信息视图。推演者可以考虑世界真相，人物只能使用职责、亲历、公开信息或实际送达的消息；私谈和不同参会范围的会议不自动共享。应当知道的核心局势必须按时送达，不能用一句“不清楚”掩盖未接通数据。

剧本若允许迟报、误判、瞒报或腐败，应分别记录世界实际情况、报告声称情况、人物/玩家当时已知情况，保留可调查线索。不能把AI记错金额或乱算比例解释成合法瞒报。已标明可用的国库值也不能临时被杜撰的冻结款否定。

## 九、季度奏报如何帮助下一轮决策

内部结算保留完整真相；玩家奏报只呈现其应知、已查明或实际送达的信息。下列“结果、原因和责任”均遵守这一范围：未知责任标待核并给线索，不能把后台隐情直接暴露给玩家；已核定公开数值也不能随意改写。

奏报应突出玩家能据此行动的内容：

1. 本季最重要的变化与结果。
2. 每项诏令／政策的实际执行、代价、受阻原因及责任。
3. 钱粮、军情、民情与其他关键指标的前后变化；分清总额、已预留、已消耗和剩余。
4. 其他势力与社会主体的反应，危机或事件怎样演变。
5. 下季仍有效的命令、在办事务、待成立条件和需要玩家取舍的事。

每条要事能追到命令、责任人或事件，支持召见相关人物、继续督办、修订原令或撤销。议事和修订带入这条报告的来源及当前局势，不让玩家反复手抄，也不把修改变成新发一遍相同命令。

玩家正文用清楚的时代语言和当前显示单位，不暴露内部状态代码。数额按已核定值准确表达，估计值和不确定性明确标注。剩余流民不等于受助人数，库存不等于本季收入，已拨专款不等于又一次支出。

## 十、前后端都随剧本适配

剧本提供玩家称谓、人物姓名及官职、机构、地区、资源名称/单位、主要指标、日历、时代措辞和支持语言；本局任免等新事实优先于开局显示资料。底座的全局翻译只保存通用操作词。

新局需要选择并核对经营剧本；读档使用本局绑定版本。前端不显示当前剧本不存在的机构、资源或能力，后端不能接受前端仅换了名称却不成立的操作。明末和三国需要相同循环、不同世界规则，不能只换皇帝名或套用同一银两/内帑/官制。

界面围绕当前局势、奏报、议事和命令组织；地区、军队、财政和派系按需要展开。先把信息和后续决策连起来，再做装饰，不堆一排权重相同的部门按钮。

## 十一、后续实际开发顺序

本轮先完成规则和原实现核对，**不继续扩写明末固定动作，也不立即增加新演示或迁移整套旧引擎**。后续按以下真实缺口推进：

1. 定经营剧本的最小资料与版本契约，用明末、三国各走一份纸面映射，暴露仍藏在底座中的专有设定。
2. 接通剧本加载/开局绑定，把人物、资源、制度、纪年、初值和具体规则移入剧本；复用已经验证的保存、幂等、原话及来源保护。
3. 建立通用命令、持续政策和修订/撤销台账，并接全局现行视图与按职责送达的信息。
4. 让AI基于这些资料提出整季候选变化，统一核对和提交；自由诏令不再受原型三个工程类别限制。
5. 接完整的奏报→议事／继续／修订／撤销交互，前端按剧本呈现。
