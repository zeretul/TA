# 人物身份、关系、聊天、记忆与通信

适用版本：0.7.0；更新：2026-11-05。本稿依据当前实现、已确认决定与既有交付记录整理。

## 统一人物

同一NPC在主故事、私聊、群聊、双修和资料页使用同一身份。作者档案、实际出场、当前在场、人物知道什么是四件不同的事；目录存在或有头像不等于已相遇、已到场或愿意合作。人物按地点、事件与相关经历取用资料，不能把全知作者材料泄露给玩家。

## 交流与关系

- 私聊只注入本人有权知道的资料；群聊使用共同可见场景、公开人物信息与对应受众历史，不能把所有成员的私聊秘密合并成共享记忆。
- 人物保留自己的口吻、目标、偏好和边界。多人不强制逐个轮番发言；指定对某人说话不自动变成现场其他人听不到的私聊。
- 好感使用现有方向性评价，关系使用正式关系事实，具体邀请使用当下意愿；高好感不自动建立道侣、朋友、组织权限或亲密活动资格。
- 新的双向关系须有双方分别表达、前后顺序和明确对象的证据；沉默、拒绝、条件未满足或同一人两句话不等于双方接受。单方断交、公开为敌按已有规则处理。
- 关系解除后，下游资格读取当前关系，不能继续沿用历史亲密身份。相同经历不因换窗口或重复感谢再结算。
- 人物成长按本局正式时间、既有规则与真实条件推进；不是后台运行整个宇宙，也不因现实离线时长自行全图模拟。

## 通信

传音、书信、主动来讯和星海无线电沿各自世界条件处理。书信区分写出、送达、收件人与回信；消息不自动等于接受邀约或已完成行动。星海远程通话需要真实设备、已获知的有效联系条件与本人可回应状态，不能买到无线电就获得全世界频道。

## 0.7.0：NPC之间的关系与正式伴侣保护

原有Relationship结构主要记录NPC与主角的关系；NPC互相之间原本已有作者设定和叙事记忆，但没有完整的专门关系图。本轮用已有Profile描述及Knowledge记录承接夫妻/道侣、父母子女、师徒、朋友、同僚等关系，不增加新的数据库、好感矩阵或关系图面板。

关系说明双方稳定身份、类型、方向、当前状态及实际依据；父亲/子女、师父/弟子不能倒置，多种关系可以并存。人物只记得实际知情的关系，私事保持对应受众；关系变化使用已有supersedes/retracts替代旧知情记录并同步当前描述，保留历史。NPC间关系不能错误写入只面向主角的relationships字段。

保护正式配偶、正妻/正式道侣以及作者明确保护的主伴侣。当前作者保护对是韩立—南宫婉、韩萧—艾默丝；绑定原生source_key，不按同名捕获自创NPC。若开局尚未成婚，不伪造当前婚姻，但不以这个时间空档供第三者攻略，也不向玩家泄露未来剧情。

解除须先有本局真实决裂并正式终止该关系的记录；已婚者须本人明确表达并实际完成离婚/解除道侣。冷战、分居、失联、高好感或玩家转述不够，不能为了开放攻略临时捏造解除事件。解除后仍由本人自主决定，并不强制接受新感情。

非正妻或非主伴侣身份不一概锁定。慕沛灵不因与韩立往来或相关非正妻身份自动禁追求；仍尊重其自身意愿、承诺和处境。这里是通用AI关系约束及既有事实保存，不是新增一套司法婚姻判定器；不能保证任何模型在任意诱导下永不偏离规则。

## 生成人物的年龄

新人物可在正式初次出场明确年龄及性别，并写入本局Profile；未知保持未知。不能按外貌推断，也不能为邀请临时改成年。已保存年龄参与邀请资格，不改变原生目录人物的年龄判断。本轮模型生成的24岁女性及父女/师承三条资料已实际保存、冷读，并由两种程序读到邀请资格。

实现新增[通用人物规则](../../../internal/character/social_identity_rules.go)，沿[原Profile](../../../internal/character/profile.go)与[Knowledge记录](../../../internal/character/memory.go)保存。完整范围见[交付记录](../../0.7.0_人物关系与三版本交付.md)。

## 当前实现边界

双修另见[独立设计](自制-双修窗口.md)。普通聊天、正式关系与通信共用已有Story记录，不另建情缘数据库、全员两两好感矩阵或强制刷礼物任务。人物个人事件卡是可取用素材，不代表全部已制作成固定个人任务线。
