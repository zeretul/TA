# 交付说明

本包是在 DENOVA 官方源码上改造的**游戏专用自制版**：一个能跑、能玩、用真实模型的最小可用版本。本文说明交付了什么、怎么用、验收到了什么程度，以及**哪些没有做**。

---

## 一、怎么进入

双击根目录的 `启动.bat`。细节见 [启动说明.md](启动说明.md)。

> **工作树试玩入口（本批新增功能所在处）**：修炼数值、物品与可玩战斗闭环这一批成果提交在 **`claude/game-only-cont` 分支的工作树**（`.claude/worktrees/game-only-cont/`）。要试玩这一批功能，请进该工作树目录，双击它自己的 `启动.bat`（脚本用 `%~dp0` 定位，会在工作树内自动构建 `TA.exe`，数据根 `.denova-game/`、端口 19720 均与主目录隔离）。
>
> **主目录的 `启动.bat` 仍指向主目录版本**，不含本批的战斗窗口与修炼数值。工作树做完不等于主目录启动器已有新功能；按交付纪律，本批**不覆盖复制文件去「交付」**，接回主目录留待统一集成步骤。本批的验证范围仅限工作树（见第三节战斗批次验收）。

## 四、设计上的几条硬约束（为什么这么做）

这几条不是随手的选择，是交付质量的关键：

1. **只有一条创建通路、一条状态提交通路。**
   剧本包只是往原有创建表单里**填初值**，故事仍然由原版 `createInteractiveStory` 创建，回合仍然由原版 `POST /api/interactive/chat` 提交。没有第二套世界状态。

2. **不迁移存储。**
   保持 DENOVA 原生的 JSON / JSONL + journal，没有引入 SQLite，没有另建可写世界状态。

3. **不覆盖用户成果。**
   剧本包写世界书时按名字去重，重复载入是空操作，用户后来手工编辑过的条目不会被冲掉。

4. **保留原版交互。**
   「点选项 → 填进输入框 → 再发送」这个节奏没变，没有加二次确认。

5. **数据根与端口独立。**
   本包不读、不写原版安装目录，也不进你真实的 `.ta-game`。

## 八、仓库卫生

- `.gitignore` 排除了凭据、用户模型配置、运行数据、测试日志、`node_modules`、缓存和构建产物；
- **没有**排除整个 `config/` 源码目录；

- 提交按文件名逐个显式暂存，**从不使用 `git add .`**；
- `.gitattributes` 固定 `*.bat` 为 CRLF（cmd 解析需要，见 [启动说明.md](启动说明.md) 第六节）。
