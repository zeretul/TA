当前最优顺序是：修目标范围缺陷及新包内容错误，逐项接通成长、学习、物品、战斗和任务的正式消费者，以凡人现有的保存、冷重开、重试及分支证据标准验收。切片用于尽快发现问题；**不是将用户要求的开放世界与全套剧本缩成两个地点的交付范围**。原设计《游玩循环与选择后果》第 7 行已明确不采纳“小区域做深”作为范围收缩。

## 二、新增缺陷与内容错误

### D01 · 设置目标选择会切换游玩故事 · P1 · 基线已复现

**来源**：`设计稿/聊天整合_资料与故事手记整改_20261029.md:104,144`、`PROJECT.md:44` 要求选设置目标只切编辑对象。基线 `web/src/features/interactive/components/game-settings/GameSettingsView.tsx:217–227,460–470` 却用全局 `currentStoryId`，先 `setStories(..., storyId)`，再 `selectInteractiveStory(storyId)`。`web/src/features/interactive/api.ts:50–53` 发实际 POST select；`internal/app/interactive_app_service.go:63–73` 保存当前故事。

**反例 M**：游玩 A，设置页选择编辑 B。原回调执行后全局变 B，并记录一次 select API 调用。预期 A 不变失败。不存在“仅视觉提示不清”的解释空间。

**修复与验收**：页面局部编辑 ID 与全局游玩 ID 分离；正文、模型/思考、规则、媒体、助手上下文、分支解析和保存回读统一沿局部目标。选择/保存 B 后返回游戏、刷新、冷重开仍玩 A；B 设置改变，A 不变。需验证两个不同世界、各两个故事及非 main 分支。HIGH 已出现局部 `editingStoryId` 和分支加载代码，属于已开始修复，**未据此销项**。

### D02 · A 世界保存的迟到响应覆盖 B 编辑器 · P1 · 基线已复现

**源码**：同组件 `saveWorldDefaults:287–316`，返回后无条件写共享 `worldDraft/worldSaved/worldRevision`；`worldSelector:475–486` 保存时仍可切目标。响应仅更新 A 的 pack，B 对象未变，依赖 B 对象的重置 effect 不重跑。`reloadWorldDefaults:326–346` 同类风险。

**反例 M**：开始保存 A→响应暂挂→切 B 并载入 B 草稿→释放 A 响应。结果：已选 B，草稿却为 A-saved，revision 为 A-new；B pack 对象未变。预期 B 草稿不变失败。

**影响边界**：确认的是错误对象的界面回填与成功提示；未证明服务器已跨世界写入，revision 冲突可能挡住后续保存。不要将其夸大成存档损坏。

**修复与验收**：保存/重载期间冻结选择，或以目标 ID/请求世代丢弃过期界面回填并更新正确缓存。慢响应 A→B→A、409、网络失败、卸载/工作区变化均需覆盖。仅添加目标标签不能解决此缺陷。03:15 已读到 HIGH 的 `disabled={worldSaving}` 修正；从“源码待修”转为“修正待组件/页面验证”，不将中间状态继续派发。
