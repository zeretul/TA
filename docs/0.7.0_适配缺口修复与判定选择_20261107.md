## 交付行为

- 通用行动世界可使用既有开局适配能力，按世界规则建立需要长期记录的状态。精确结算世界保留自己的模板和规则；既有判定引用的数值字段不能被开局适配改写范围、类型或初值。
- 生成与导入的规则条目省略加载方式时默认常驻；模型生成保留关键词和加载方式。作者明确指定的按需或手动取用不覆盖，知情过滤继续生效。核心正文建议合计不超过 32KB，沿用现有常驻资料安全上限与超限报错，不静默截断整个世界书。
- 派生模块使用与保存、读取一致的规范形式比较。裁剪物品、技能生成目录后可以保存与重载，不靠补回删除内容掩盖差异。
- 声明修仙玩法的包必须带冻结参数。创建草稿明确选择修仙模板时可复制参考参数后归包保存；包运行时不通过缺参数借用程序默认世界。
- 知情限制必须指向包内实际条目 ID；改 ID 时必须同步限制。修仙包也校验已支持的通讯和开场声明。
- 回合判定可在兼容选项中选择，世界推荐单独分组和标示。新局默认与当前故事分别保存；切换同步回合实际使用的冻结判定，保留角色状态、世界归属和进度。正在生成的回合不允许中途更换判定。

新局默认写入世界的设置覆盖文件，作者包不改；清除覆盖即回到推荐。已开局故事按自己的选择运行，其他故事不随之改动。依赖另一套角色字段的判定会被过滤并由后端拒绝。

## 真实模型追加发现与修复

HY4FREE 实际读取资料后，两次初始化仍返回 `lore_not_reviewed`。核对工具参数和返回 ID 后确认，原有读取回调未接入本轮开局校验。这是固定模板时期未暴露的连接缺口。

现已将成功全文读取的后端 ID 经现有工具上下文回传到当前开局草稿；完整常驻上下文成功组装后也记入凭据。只看索引、未返回的条目和其他世界的资料不产生凭据。模型不能自行声明“已读”。五种实际工具链用例及应用回合装配复验通过。

## HY4FREE 真实验证

通过 WB 的 `hy4free` 实际生成、保存并启动“灯印岛”，没有预置特殊机制结果，也没有添加灯印专用程序。世界有 8 条资料，其中两条核心规则常驻。

| 实际回合 | 正文与正式存档结果 |
| --- | --- |
| 开局 | AI 增加“见证灯状态”枚举，移除无用生命/等级字段，保留判定使用的观察；灯未亮，没有约定 |
| 缺少条件 | 明确自愿、见证人在场，但灯未亮，因此没有灯印或新增册页记录 |
| 条件齐全 | 处理潮湿灯芯后点灯，再当面重述承诺，才生成灯印；没有追认前一轮无效的话 |
| 熄灯与未到期 | 灯状态变为熄灭，先前灯印与约定保留；今天尚未到明天，没有判成违约 |

承诺写入人物记忆、场景及角色事实。实际下一轮上下文中包含两条核心规则。冷重开保持四回合事实；从第二回合建出的分支保留未点灯、未立约的状态，不带入后续结果。实际切换到电影英雄判定后，状态不变，冻结判定改变并能在第二次重启后读回。

开局使用默认规划；后三步隔离测试选择关闭额外规划、目标 600 字。模型发生可修正的工具参数格式错误，按现有反馈重试后正式提交。此验证证明该单一机制样例的完整链路，不代表所有未来规则或模型推理都已穷尽验证。

WB 初期授权失败、Node 验证脚本默认响应头等待上限中断、修复前“已读”卡住的失败记录全部保留。修正等待设置后没有给模型总运行时间加上限。停止故障测试请求后，旧会话拒绝直接开启新命令；保留旧记录，从已生成的同一个包创建全新隔离故事完成上述验证。没有使用旧档迁移或删除私人存档。
