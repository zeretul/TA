# 0.7.0 人物关系与三版本交付

日期：2026-11-05。开发版、正式本地游玩版与分享版均更新为0.7.0。

## 玩家行为

- AI生成且没有原生source_key的NPC，可凭本局正式保存的成年年龄参与邀请资格检查。仍需在场、性别明确且与主角异性，并由本人回应是否愿意。
- 原生NPC继续按冻结目录及正式时间判断年龄；不能用另一份Profile年龄盖过目录中的未成年记录。未知年龄、未满18岁和伪造source_key不放行。
- 通用AI规则明确NPC之间的夫妻/道侣、父母子女、师徒、朋友、同僚等关系，保存双方身份、方向、当前状态与依据，按知情范围和已有替代/撤回记录承接。
- 正妻、正式配偶/道侣及明确主伴侣关系存续时拒绝第三人追求。保护对为韩立—南宫婉、韩萧—艾默丝，按原生身份绑定，不按重名捕获自创角色。
- 只有本局真实决裂、关系正式结束后才重新考虑；已婚者需要本人明确离婚/解除道侣并实际完成。吵架、分居、失联、高好感或玩家代传的话不等于离婚。
- 开局尚未成婚时不伪造“已经结婚”，也不利用时间空档绕过作者官配保护。慕沛灵等非正妻身份不一概禁追求，仍尊重本人意愿，关系结束也不强制答应新人。

原来已有NPC设定和知情记忆；正式Relationship结构主要表示NPC与主角。本轮复用Profile与Knowledge保存NPC间关系，没有新增关系数据库或图谱界面。主伴侣限制属于AI规则与现有事实承接，不能承诺任意模型在任何诱导下永不偏离；本轮没有越过用户授权去增加一套程序婚姻锁。

## 修改范围

通用人物规则集中在[规则文件](../internal/character/social_identity_rules.go)，接入主故事、普通聊天、群聊和相关人物的上下文。年龄与关系信息沿原有Profile/Knowledge提交和Story保存。

本地双修服务只修改用户单独批准的成年资格读取。与备份逐段比较，其他流程没有变化；其他Agent的双修提示词、模型辅助文件和相关测试文件哈希保持不变。本轮没有调用或优化其成人向演绎。

分享从未修改该部分的0.6.18最终源码基线维护，补入公共修复与本轮规则；保留标准非露骨提示词。公共的明确拒绝、JSON兼容与格式协议修复仍保留。以[干净基线](../tools/release/share-baseline/README.md)及[构建脚本](../scripts/build-editions.ps1)持续维护，不能拿旧整包覆盖最新公共功能。

## 实际验证

- 年龄资格、原生未成年保护、性别/在场约束、NPC关系方向/隐私/替代历史、存档冷读的针对性回归通过。
- 人物模块完整回归及相关四个模块静态检查通过。检查中发现新增通用文字挤占无关NPC记忆预算，已改为公共提示统一注入、相关人物才补专属边界，原记忆回归再次通过。
- 分享基线的邀请、明确拒绝、原有活动及提示词相关回归通过。
- 前端类型检查和生产构建通过；两种程序共用同一份0.7.0前端，更新器也构建为0.7.0。
- 使用本机现有Gemini配置完成6个独立模型场景。请求模型gemini-3.8-flash-high，实际返回标识gemini-3.8-flash-n；没有改本机配置。
- 南宫婉在关系存续时拒绝；艾默丝不接受玩家单方“离婚通知”；正式解除关系后人物仍可自主拒绝；慕沛灵没有被误判为正妻硬锁；父亲与师父正确区分。
- 真实模型生成24岁女性林枝、48岁父亲林远及3条父女/师承知情资料，经正式Story接口写入隔离档，关闭重开后仍为2人、3条资料。
- local/share构建均在独立端口启动，读取该档时林枝进入可邀请名单，同性父亲不进入。安装后的正式程序与分享程序又分别以隔离数据完成相同读回，首页正常返回。

这些是6个独立人物提示词检查及明确的保存/启动路径，不冒称6个完整主故事游玩回合、全量新剧情或成人向演绎验收。启动有sonic优化库兼容提示，实际回退标准JSON后正常运行，没有因此改动账户或安全设置。
