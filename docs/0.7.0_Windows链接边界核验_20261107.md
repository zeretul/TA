# 0.7.0 Windows 链接边界核验

日期：2026-11-07。范围：用户追问的工作区 6 项跳过测试，以及同一真实路径解析问题影响到的项目登记、审阅服务和文件锁。开发目录为 `E:/游戏/游戏开发/TA-开发版`；未操作历史推演工作树、Git 历史或共享依赖。

## 本机实际补验与发现

Windows 目录联接（junction）无需上述权限。本轮用 Windows 原生 API 在隔离临时目录创建真实目录联接，覆盖原有目录场景，同时补充账本文件名被目录联接占用的拒绝场景、项目身份、文件锁、审阅服务、长中文路径、旧目录迁移和自动发现，共 12 项目录联接测试。清理只移除联接本身，不递归穿越目标。

修复前实测发现：

1. 私有变更存储目录中的联接已被拒绝，但返回普通路径错误而不是产品约定的 conflict；已修正错误类型。未观察到外部目录写入。
2. Go 当前的 `filepath.EvalSymlinks` 未解析 Windows 目录联接，变更/审阅服务从联接入口打开工作区失败。新增 `localfs.CanonicalPath`，Windows 通过打开现有路径并取得最终路径，其他平台继续使用标准符号链接解析。
3. 同一目录从联接入口登记，会产生第二个 Project ID。项目登记与路径比较已采用相同的真实路径解析；文件锁的现有路径前缀也统一解析，并验证联接入口不能绕过已持有的文件锁。修复前只复现锁路径字符串不一致，没有证据证明操作系统文件锁曾被绕过。

解析后的绝对路径仅用于宿主运行时；没有改 ProjectID、受管项目相对路径格式或存档格式，也没有自动合并已有重复项目。实现参考 [Microsoft GetFinalPathNameByHandleW 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。

## 不能等同为通过的部分

目录联接不是文件符号链接。尤其账本文件指向外部文件的原始用例，当前主机仍未运行到行为断言；新增“账本文件名被目录联接占用”检查不能冒充它。原 6 项真实符号链接用例没有宣称全部通过。

本轮未实测网络共享路径（UNC）、其他操作系统的运行行为或远程模型调用。全量测试中其他外部运行时/发布审计/平台专属可选用例的跳过单独保留，不计为本批 6 项已验证。

## 同轮追问：四世界的世界书条目差异

界面 `worldPack.settings.content.world` 显示“世界书 X 条”，后端 `Pack.Summary()` 的计数为 `len(p.World)`，不是可执行玩法规则总数。核对当前作者 JSON：

| 世界 | 总条目 | 人物 | 非人物 | 正文字符数 |
| --- | ---: | ---: | ---: | ---: |
| 凡人修仙 | 123 | 107 | 16 | 68,529 |
| 澜川群侠 | 274 | 60 | 214 | 88,351 |
| 星海争锋 | 273 | 60 | 213 | 55,404 |
| 碎冠诸境 | 370 | 60 | 310 | 52,538 |

凡人的人物条目较多，非人物内容集中在 11 条 world 和 5 条 rule；其他三包大量独立拆分 item、setting、location、event、faction。修仙物品、技艺等还存在独立内置目录/规则实现，不由世界书总数体现。字符数包含标点等，不能等同文学字数或证明内容齐全。

结论：不是该计数遗漏，但内容组织粒度明显不一致。凡人的地点、势力与日常设定是否存在实质缺口，需要逐类内容审计；本轮未做该完整性审计，也没有为了凑数量扩写世界包。统计证据为 `world-book-counts.json`。

## 全量跳过清单的口径

`root-skips.json` 逐项保存主模块全量回归的跳过原因。除本批明确核验的 6 项及相关项目模块 2 项外，还包括未指定外部 Claude/Codex 可执行程序的集成用例、显式启用的浏览器/资源发布审计、POSIX 专有权限检查、其他包的符号链接权限检查和可选夹具生成。它们保留为未覆盖项，不算通过，也不混入原 6 项的数量。全量回归的“0 失败”仅对实际执行的断言成立。

最终机器可读结果见 `verification.json`。本轮没有使用改为成功返回、放宽断言或延长等待来消除失败；复现问题已先失败、修复后通过。公开链接只是 API 实现依据，所有通过结果来自本机实际执行。
