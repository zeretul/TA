# 文档地图：哪些是当前设计，哪些是历史记录

日期：2026-11-10。这份文件给接手开发的人（含 AI 助手）用：仓库 `docs/` 下有一百多份带日期的交付记录，其中**只有少数描述当前设计**，其余是过去某次交付的现场记录。按错文档做决策会重复造轮子或推翻已定方案。

**如果你是从云端接手的开发方，先读 [NOTION 开发任务书](NOTION_开发任务书.md)**，那里说明当前任务、读文档顺序和硬性边界。

## 读文档的规则

1. **先看日期**。文件名或正文里的日期是权威时间戳。旧文档里的"当前版本""待办""测试数字"只在该日期有效。
2. **设计看无日期或最新日期的方案文档，状态看 `progress.md`**。历史交付记录只用来查证"当时为什么这么定"，不用来查"现在是什么样"。
3. **代码、测试和根目录 `AGENTS.md` 是长期不变量的事实源**。文档与源码冲突时以源码为准，并按需修正文档。
4. **`AGENTS.md` 里"当前进行中"的段落可能已过期**。它记录的是编写时的状态。

## 历史交付记录（按日期解释，不代表当前状态）

`docs/` 根目录下 `0.6.x_*`、`0.7.0_*_2026MMDD.md`、`TA_*_2026MMDD.md`、`本机*`、`目录整理*`、`开发缓存*` 等命名的文件，都是某次交付或核验的现场记录。它们包含当时的路径、测试数字和结论，**会与当前源码不一致**。

这些文件里有大量本机绝对路径（`E:/游戏/游戏开发/...`、`C:/Users/...`），其中部分指向已迁移或删除的目录。这是历史记录的正常形态，不是仓库配置错误。**不要按这些路径去找文件**，也不要据此推断当前目录结构。

同样，文档中出现的 `DENOVA` 是项目早期名称与遗留环境变量（`DENOVA_DIR` 仍作为 `TA_DIR` 的兼容回退存在于 `config/config.go`）。项目现已完全自制，新代码和新文档不要再使用该名称。

## 本仓库没有的内容

- **前端构建产物**：`web/dist`、`internal/webfs/dist` 未入库，用 `pnpm --dir web build` 生成。
- **运行数据**：`dev-data/`、`.ta-game`、`config.toml`、存档、会话、日志、凭证一律不在仓库内。
- **完整源码副本**：`docs/交付资料/云端/` 下的历史源码包未入库。
- **作者原始资料**：`五世界作者资料`、`候选剧本` 未入库。
- **归档与压缩包**：handoff/云端接续归档、恢复核验 zip、旧备份全部只在本机。
