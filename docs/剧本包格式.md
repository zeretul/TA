# 剧本包格式

剧本包（story pack）是本包引入的**最小剧本加载单元**：把一条故事线的开局、主角、世界书和玩法模块绑定打包成一个目录级交付物，让一个可玩的世界以单个文件的形式提供，而不是靠手工拼装一堆目录项。

一句话定位：**剧本包是一种打包格式，不是一条新的游戏通路。** 载入剧本包不会创建第二套世界状态，也不会绕过原有的创建/推进链路。

---

## 一、放在哪里

```
<数据根>/presets/story-packs/<剧本包 ID>.json
```

默认数据根是 `<本包目录>\.ta-game\`，所以完整路径形如：

```
E:\游戏\游戏开发\DENOVA自制版\.ta-game\presets\story-packs\my-world.json
```

剧本包与文风、事件包、检定系统等目录项同属 `presets/` 下的用户级预设目录（见 `internal/presetlayout/layout.go`）。目录不存在时不需要手动创建，放文件进去即可；`presets/story-packs/` 会在读取时被识别。

**文件名必须与包内 `id` 一致。** 列表按文件名索引，读取按 `id` 查找；两者不一致的包会被判为无效并在列表中明确报错，而不是"看得见却点不开"。

**内置剧本包**编译在 `TA.exe` 里（`internal/storypack/builtin.go`），首次运行就能用，不需要任何文件。如果在 `presets/story-packs/` 下放了**同 ID** 的文件，文件版本会覆盖内置版本。

## 二、最小可用样例

```json
{
  "version": 1,
  "id": "my-world",
  "name": "我的世界",
  "description": "一句话介绍这个世界。",
  "tags": ["标签一", "标签二"],
  "story": {
    "title": "我的世界",
    "origin": "故事从什么地方开始，交代时代、地点和主角处境。",
    "protagonist_name": "主角名",
    "protagonist": "主角的身份、性格、能力和处境。",
    "reply_target_chars": 2500,
    "choice_count": 3,
    "opening_text": "首幕正文。留空则由模型根据 origin 生成。",
    "module_refs": {
      "event_package_ids": ["default"],
      "rule_system_id": "dm-gritty-survival",
      "actor_state_id": "default",
      "image_preset_id": "game-cg"
    }
  },
  "world": [
    {
      "id": "my-world-place",
      "name": "地名",
      "type": "location",
      "importance": "high",
      "tags": ["世界设定"],
      "keywords": ["关键词一", "关键词二"],
      "load_mode": "resident",
      "brief_description": "一句话摘要。",
      "content": "这一条世界书的完整内容。"
    }
  ]
}
```

---

## 三、字段说明

### 顶层

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 目前只接受 `1`。更高版本会被拒绝，而不是猜着读。 |
| `id` | 是 | 剧本包 ID，**必须与文件名一致**（`<id>.json`）。不一致会被判为无效。不能含 `/\:*?"<>|`，不能含 `..`。 |
| `name` | 是 | 界面上显示的名字。 |
| `description` | 否 | 选择器里的简介。 |
| `tags` | 否 | 标签，仅用于展示。 |
| `story` | 是 | 故事初始值，见下。 |
| `world` | 否 | 世界书条目，见下。 |

### `story`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 故事线标题。 |
| `origin` | 是 | 故事起点设定。 |
| `protagonist_name` | 否 | 主角名。填了就使用自定义主角；留空则用默认主角。 |
| `protagonist` | 否 | 主角档案。 |
| `reply_target_chars` | 否 | 每轮正文目标字数。留空取 2500。 |
| `choice_count` | 否 | 每轮选项数。留空取 3。 |
| `opening_text` | 否 | 预置首幕正文。**填了就用它，不再让模型生成首幕**；留空则按 `origin` 由模型生成。 |
| `module_refs` | 否 | 玩法模块绑定，见下。 |

### `module_refs`

这就是剧本包接到原有玩法模块上的挂钩（对应代码里的 `StoryDirectorModuleRefs`）。每一项留空都会落回原版新建面板的默认值，所以**只写你真正要改的那几项**。

**这里写下的模块必须真实存在。** 载入剧本包时会逐个解析这些引用；任何一个找不到，该包会被判为无效，列表里带上"所需模块不存在"的说明，读取时也会明确报错。这是刻意的：一个依赖你没装的检定系统的世界，如果静默退回默认检定，你玩到的就不是作者写的那个游戏。把对应模块装进 `<数据根>/presets/rule-systems/`（或对应目录）后重新读取即可，不需要重启。

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `event_package_ids` | `["default"]` | 事件包。 |
| `rule_system_id` | `default` | 判定规则系统。可选 `default` / `dm-fail-forward` / `dm-osr-player-skill` / `dm-cinematic-heroic` / `dm-gritty-survival` / `dm-mystery-clue-forward` / `dm-drama-stakes`。 |
| `actor_state_id` | `default` | 角色状态模块。 |
| `image_preset_id` | `game-cg` | 配图预设。 |

**剧本包不写文风。** 早先的格式允许 `narrative_style_id`，现在这个键会被忽略（旧包仍然能正常载入，只是那一项不再生效）。文风是玩家的选择：同一个世界可以用正剧讲，也可以用轻快讲，换一个剧本包不应该连带换掉讲述的语气。主叙事、对白与聊天、战斗描写这三项用途在故事设定里各自选择，新建故事默认跟随主叙事。

### `world[]`

每个条目会写进工作区的资料库（世界书），从第一轮起就对模型可见。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 条目 ID，包内唯一。 |
| `name` | 是 | 条目名。**去重按「世界范围 + 条目名」判定**：同一个包里不会重复写入同名条目，也不会覆盖已有条目；别的世界（别的剧本包）定义同名条目互不影响，两个世界各自看到自己那份。 |
| `type` | 否 | 类型，如 `setting` / `location` / `character` / `item` / `faction`。 |
| `importance` | 否 | 如 `high` / `medium` / `low`。 |
| `tags` / `keywords` | 否 | 分类与检索关键词。 |
| `load_mode` | 否 | `resident`（常驻）/ `auto`（按需加载）。 |
| `brief_description` | 否 | 一句话摘要。 |
| `content` | 是 | 条目正文。 |

## 四、载入剧本包时发生了什么

1. 前端调用 `POST /api/projects/:projectId/story-packs/:id/apply`。
2. 后端把 `world[]` 写进该工作区的资料库，条目标记为这个剧本包的世界范围（scope），**跳过本世界内已存在的同名条目**。
3. 后端返回一份草稿：包 ID、包名、新写入条数、已存在条数，以及一份标准的创建请求。
4. 前端把草稿**填进新建面板的表单**——主角、开局、模块绑定、字数、选项数。
5. 你确认（或继续修改）后点「开始」，走的是**原版 `createInteractiveStory`**。
6. 后续每一轮推进，仍然走**原版 `POST /api/interactive/chat`**。

所以：

- 只有一处创建故事线，只有一处提交回合状态；
- 剧本包不新建预设库、不改目录、不写第二份世界状态；
- 载入是幂等的：重复载入同一个包，新写入 0 条，你后来手工改过的条目不会被覆盖；
- 包里的每个字段都只是**初始值**，载入后仍然可改。

## 五、校验与排错

- 包解析失败或字段不合法时，它**仍会出现在选择器里**，但标为无效并给出原因，而不是静默消失。这样坏文件可以被发现和修复。
- 常见的无效原因：
  - `version` 不是 1；
  - 缺 `name`、`story.title` 或 `story.origin`；
  - `world[]` 里某条缺 `id` 或 `name`；
  - `world[]` 里有重复的 `id`；
  - `id` 含非法字符。
