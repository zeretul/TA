# 0.6.17 规则内 AI 生成、制作与改制

本轮在已核验的 0.6.17 源码继续开发；没有用旧 Git HEAD 或旧包覆盖现有改动，没有安装、发布或接入玩家存档。

## 已实现

### 武侠与星海

- `generate.design` 可提出真正不同的技能效果、装备主属性和制作产物，而非只换名字。
- 技能可组合已学、同尺度基础中的攻击、防御、治疗、控制、毒与载具维修。每类至多一次、最多三类；需要额外已学基础才能加入新效果，复杂条件技能不开放自由重组。
- 实际总效果预算驱动最低能量消耗、所需境界/火候及研习工时。生成新技能必须投入玩家授权的实际工时，之后直接进入现有施展与战斗消费者。
- 装备改制需要一件真实持有、未装备或部署的实物和适用制作方法。材料、专业、作业设备、燃料和时间真实结算；改制不复制原物，已有载具磨损、燃料及动力锁定不被重置。
- 新制作方法可以登记本局新产物定义。登记不获得物品；之后的 `craft` 按现有制作流程扣料、耗时、产出。强度可以超过基础，不能超过现有领域上限或绕过专业门槛。
- 材料仍是当前目录中可计价的真实材料。基础核心材料不能消失；额外组合可由 AI 提案，规则检查成本价值，不模拟独立材料物性系统。
- 新产物继续支持真实装备/使用、交易、模板能力识别、详情和可选配图。原有孤品、充能/冷却物件的复制限制保留。

### 修仙

- `skills[].craft_design` 从已有技艺方法推导同一技艺适用的新产物，复用原生品级预算、境界、库存、失败率、工具和地点条件，不另造炼丹/炼器引擎。
- 可以选择更高品级的非独特模板，再提议主属性与运转成本。材料和批次工时随产物价值增加；学习与制作门槛至少达到产物适用境界。
- 法器、护具、法宝的主属性，阵法增攻/防护选择，恢复丹药的生命/灵力用途，均使用已有真实消费者。不存在的特殊效果不能用自由字符串登记。
- `skills[].skill_design` 可调整已批准战斗形态的威力、目标数、命中、穿透或护盾强度/时长。更强效果同时提高耗灵、经脉负担和研习时间，保留法器要求、准备、残伤及恢复条件。
- `techniques.learn[].design` 可在原功法专长预算内重新分配六项实际属性。正收益预算不能增加，负面代价不能减少；兼修、成长、突破、境界上限和学习时间仍由该功法的规则控制。
- 注册方法或技能不等于制造产物或完成学习。正式制作产物不能再用 `items.acquire` 重复领取。

### 共通

- 六色品级、简介、背景和实际资格仍可显示。颜色只是展示，不替代数值预算。
- 新生成定义只写本局；同名稳定身份不能改写既有机制。旧分支不会获得未来生成物。
- 保存可重新推导的设计提案，冷重放重新通过原生规则检查；输入克隆保护避免已接受提案被后续对象修改。
- 可选配图继续复用已有队列与持久去重，新配方的产物也能成为独立配图目标。没有图像 agent 时不会伪造图片。

## 明确剩余与边界

- 这不是任意效果脚本语言。复杂条件技能、复活、量子通信、充能/冷却物品等没有新增自由组合消费实现；仍使用原模板或拒绝设计，不称为已自由生成。
- 本轮没有改变冻结世界包作者配方，没有设计自动随机掉落或材料物性系统。
- 没有调用自然游戏模型或图像 agent；规则夹具不证明 AI 会自行提出令人满意的设计、材料叙事或长期平衡。
- 未开展本轮新详情内容的真实页面视觉验收，也没有 Windows 原生运行；由总集成阶段决定补充范围。

## N05 长期容量补充（2026-11-03，可验收切片）

已实现的范围：

- 将历史生成档案与每轮规则/模型上下文分开。旧64/512项限制改为独立的16384项与4MiB存档安全闸；达到安全闸不截断旧内容，新登记在库存/学习提交前拒绝。4MiB给现有16MiB单行日志协议留出空间，并非无限容量承诺。
- 修仙物品、制作方法、战斗技能目录使用分支快照内按ID验证与局部缓存。构建目录不扫描历史定义；显式枚举仍可读取全部有效记录。没有进程全局缓存，旧分支不共享未来定义。
- 冒险目录仅展开角色真实引用、本次动作精确目标及最近32项。旧配方不在当前工作集时，仍可按ID实际制作、结算材料和时间。生成档案不再挤占冻结作者目录的256/512数量和96KiB提示预算，生成规则仍通过同一机械校验。
- 模型规则与状态手册的生成档案投影有界，制作提示先选身份再推导机制；可选配图先比新旧身份，只验证新条目，不把历史档案变成配图积压。
- 新增真实只读工具 `search_generated_definitions`，已接入既有游戏工具注册。支持精确ID、名称子串、类别和分页，返回重新验证的实际机制，以及主人公当下的学习/持有记录。游标绑定故事、分支、head与查询；结果默认最多64KiB，按完整定义截页，不截半条。
- 补修拒绝后的同批次身份隔离：容量拒绝的临时技能登记不能让后续同名请求绕过档案检查；由运行目录返回空档案分支时也不会泄漏生成定义。

已通过的规模验证（Linux，合成夹具）：

- 4096条修仙档案按ID读取，查找分配数量不随档案规模上升；2048条冒险配方仍能调用最早配方并实扣材料/时间；1024个已学生成技能不突破模型目录预算。
- 1200条修仙、1024条冒险档案通过正式Store日志、后续新登记、分支隔离和冷重开；旧配方重开后仍可实际制作。
- 安全字节闸、重复稳定身份、档案不被上下文裁剪、局部缓存及真实工具只读注册覆盖。
- 最终生成/容量定向回归通过：interactive 5.605s，cultivation 0.003s，agents/tools 0.043s。最后补充的生成配方产物自身ID检索、同批次拒绝、空分支隔离与工具查询回归再次通过：interactive 0.163s，agents/tools 0.040s。共新增11个顶层回归及2个分规模基准。

仍未完成，不按完成验收：

- 持久化仍复用既有Actor State整字段日志与快照，不是独立分片或增量归档数据库；档案登记、冒险索引及快照读取仍有O(N)工作，增长安全闸不是无限长期存储方案。
- 老定义检索已给模型真实工具，但没有新增玩家的独立档案分页UI；现有详情窗口完整列举可能仍随实际已学/持有量增长。
- 缺少自然模型跨数千回合及真实大存档长时间运行验证；合成冷重放与基准不等于该验收。
