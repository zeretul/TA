# ITER3：借网游的决策深度，不借日常负担

日期：2026-11-03。Astra ULTRA 研究、源码核对与实施契约。

本稿是独立 ITER3 增量，不覆盖已冻结 ITER2。当前实施根为 `ta_iter3_20261103/source/TA-DOT-ITER3-20261103`。本稿冻结的是下面的有限非战斗协作切片，不代表完整队伍、势力模拟或流派系统已完成；实际验证结果另由实施报告记录。

## 0. 用户边界与本轮结论

用户希望借鉴网游玩法，但明确不要每日任务和费时间的留存套路。因此本轮不做签到、日/周刷新、活动打卡、低概率掉落、累计重复次数、强制等待、拍卖行/公会空壳。准备仍可花真实材料和世界内时间，但每次输入须带来信息、选择或实际结果，不能把长劳动链当耐玩。

**本轮只实现一条新循环：亲自发现线索 → 自主选择是否分享 → 与确实在场且愿意的 NPC 共同研判 → 带着一次性方案自己行动 → 按实际结果回访交流。**

它不是“问一句得到减压增益”：交流和同意本身不产生能力。必须实际共事、各付自己的成本，产生绑定当前场地实例的方案；场地行动正式消费该方案。NPC 只承担具体分工，不代替主角学会技能、进入深处、战斗或处理核心发现。

首片使用已有三处探索，不再新增三套副本/任务平台。原普通、专长、强行、退出、保全与拆取均保留。所有分钟均为正式**游戏世界时间**，不是现实等待进度条。

### 为什么暂不做一套新流派系统

当前已有修仙功法兼容/运转、装备槽与驱动成本（`internal/cultivation/technique.go`、`combat_session.go`）；武侠/星海已有 `RequiredTool`、`ConditionalEffects`、封穴/反震/汲取/护盾、尺度与能量等真实消费者（`adventure_rules.go`、`adventure_combat.go` 等）。这些不能重命名为本轮新构筑。

要新增有价值的构筑，至少须同时交付：两种互不统治的组合、能揭示其优劣的两种遭遇、战前可理解的信息、失败后可换法及三题材规则对齐。只加三个被动加成或配装收藏不是完整玩法；同时实现会扩大本轮战斗平衡范围。后续应从现有真实组合和反制遭遇入手，而非再造自由数值天赋树。

## 3. 已有消费者与真正新增的边界

- `internal/quest/choices.go` 已有前置、真实成本、成功/失败、延期 Echo；`story_quest_choices.go` 当前明确只支持 AdventureRules 且以主角结算。不要为协作强塞第三套题材或重写任务接受语义。
- `internal/character/affinity.go` 已有单一态度值、基于事实的去重，且明确好感不是硬解锁。`memory.go` 已有亲历/转述和知情范围。
- `character.Matter` 已有 permission/action/promise、ExchangeID/SourceEventID/SettledBy；`Letter` 是已有专用结构的先例。普通 Promise 的自然语言不能被字符串解析为协作资格。
- `character.Group` 明确群聊不创建队伍；`story_combat_encounter.go` 明确好感/关系不证明同行，不能擅把 NPC 拉进玩家战斗侧。
- ITER2 `ExploreApproachInput` / `ExploreViewContext` 已有只由 Story 提供的可信 Capabilities。新增方法资格可由真实协作状态派生，不必制造一个可被普通 discover 伪造的“方案事实”，也不新增第二库存。

**真正新增**：有来源的具体协作意愿 → 两个角色实际共事与成本 → 绑定实例的一次性方法资格 → 现场消费 → 真实结果再告知。它可供后续具体合作场景复用，但首片只有下面三项，不是任意 NPC 的万能服务接口。

### 4.1 共同结果与策略差别

每个对应场地只加 `<realm>.assisted_slow`：`Kind=approach`、入口区域、需要本实例 `.clue`、`ExclusiveGroup=ingress`、20分钟、压力 +0，解析原来的核心障碍并开放原核心连接。它要求对应 `CooperationProjectID` 的实际 work 已完成，且方案未使用；不是只要和 NPC 说过话。

- 普通独行：调查10分钟/+1 → 慢行20分钟/+1；不分享信息、不求人、不需要专门技能。
- 原专长独行：通常10分钟/+0，可跳调查；仍然更快、无须找 NPC，永久学技的价值保留。
- 协作：必须先亲查10分钟/+1 → 自主分享并共同作业10分钟 → 玩家再实地20分钟/+0。星海还要真实往返现有道路并消耗材料。优点是未掌握专长者可以留出一格现场余地；缺点是更多行动、公开一条发现、依赖对方当时意愿与真实成本。
- 强行与先取部分离开仍合法。已有 `ingress` 互斥禁止把几种进入方法叠加；NPC 没有完成核心的保全/拆取，那个决定仍由玩家作。

协作不降低已经累计的压力，不重置受挫，不增加角色属性，不直接发材料，不直接开回访侧路。它让“找人一起解决一个问题”成为有实际结果的第三种准备方式，但不是所有路线最优解。

### 4.2 分享、允许和退出

玩家可以只问对方是否愿意，也可以明确展示这一条调查记录。只有明确共享的已知 `.clue` 可以进入对方记忆；不要把整个地图、背包、秘密或作者资料一并交给 NPC。玩家不愿分享时可继续普通独行。

能力合适不等于愿意。NPC 可接受或拒绝这个限定分工，仍用自由人物语言表达，不固定唯一台词。好感再高也不能替代真实在场、源技能、能量、材料和本人的答应。

如果玩家已经分享而对方随后拒绝，对方知道已听到的内容，但不生成方案、不扣作业资源、不暗推作业时间；这是信息已经说出口的真实后果。若未分享，则不能仅因问了一句就泄露线索。

工作完成后玩家也可改走别法或离开。已做的工作和真实耗材不退款；不会因此强制继续、强制扣关系或迫使等待。计划绑定原实例，不可带去另一洞窟或串用平行分支未来的工作；检查点已存在事实的合法继承见第9节。

## 5. 回访不是再领奖

共事时只知道玩家共享的记录。NPC 没有亲眼见到后来核心被保全、拆取或受挫，不能在玩家回来以前自动全知。

新增 `report` 只接受该实例已经提交的结果来源：实际 ingress、核心 disposition、setback、真实 side 到达，首片至多这四类，每类只计一个真实来源；只包含玩家本次决定告知的已知部分。至少有一个尚未报告的真实后果才形成新报告。它写入现有知情/记忆与协作记录，不发第二份物资、不重复给好感，不把整个历史重新注入。

- 赵灵能分清自己核记过什么，回来听到什么，记录是否被现场证实；不凭这次共事升级修为。
- 宋老橹能在再次交流时引用本次实际水势和玩家选的走法，不把安全建议说成自己随队取得全部战果。
- 席尔瓦能知道标记束是否实际使用、辅助电源后来怎样，但不会因此知道隐藏私密通信或获得他人的设备。

报告/来访可先不做；没有日限、倒计时惩罚或领取红点。真实长期收益仍由原处置消费者承担：材料进入库存、保全后的侧区和真实发现捷径。合作让人物也成为这段经历的有限知情者，不复刻一次通路奖励。

## 6. 最小数据与正式提交契约

### 6.1 定义与持久化

`CooperationProjectDefinition` 只定义上表三个注册项目：稳定 ID/版本、世界/外部地点、目标 RealmID、NPC SourceKey、所需调查方法/线索、双方分工说明、固定工作时长、NPC 实际技能引用、玩家实际物品成本、目标 assisted_slow ID。费用从冻结技能/物品目录解释，客户端不能上传自定义成本或奖励。

沿用 `character.Matter` 的既有 journal 与来源链，加一个受专用提交路径控制的可选 `Cooperation` 结构即可，不另造账户、库存或可写合作账本。建议必要字段：

```
ProjectID / ProjectVersion
RealmInstanceID
PartnerActorID（可复用 Matter.CharacterID，不重复存两份真值）
ConsentExchangeID / SharedDiscoverySourceRef
Phase: agreed | worked | used | reported
WorkSourceRef / UsedBy / ReportSourceRefs
```

同一分支、同一项目、同一实例只可有一份有效工作结果；更换措辞/请求 ID/离开重进不能再做一份。`worked` 表示确已付成本共事，`used` 表示现场动作消费过方案。退出不重置，读面板不改变阶段。原 `MatterStatus` 仍表达事情是否开放/已了结，不用好感值代替阶段。

### 6.2 同意与同回合规则

普通 promise、用户一句“他答应了”、新建群聊和自由 state_changes 都不是协作授权。可用同意须来自本人可追溯的已提交 Exchange/Matter，且固定项目、角色和实例一致。

**不要求为了工程方便空转一回合。** 同一正式提交可按序处理“玩家明确共享并提出具体协作 → 真正在场 NPC 的有来源回应 → 若接受则实际工作”。这种同回合回应只能作为 NPC 同意候选，经专用验证后由服务生成 Cooperation 数据；不得允许模型直接填任意参与者/成本/收益成为事实。人物存在/在场、源技能、已有线索和物品资格全部读提交前快照，同回合新出场、新授技、凭空新增物品不能自授权。

本人拒绝是正常结果：保留实际发生的对话和已明确共享的事实，工作不执行、不付成本。本人已同意但资源不足时，可以保留 `agreed` 意愿并明确本次未工作，玩家可补资源或独行；不得误记为 `worked`。现有已提交同意可以直接 work；同意不需要重复审批。若现有角色回复链不能验证某种同回合来源，禁止该来源而保留已有正式 Exchange 路径，不能以放宽信任伪称支持。

### 6.3 双方成本、同一时钟与方案消费

- work 计划先校验提交前双方状态、实际同场、源资格、协议范围、玩家材料，生成双方 ActorOps、协作状态、知情记录和唯一时钟变化，再一起提交。
- 双方同时工作10分钟，StoryClock只推进600秒，不计成20分钟。NPC在这600秒不能同时自动训练或恢复抵销已扣能量；使用/扩展现有 NPC interval growth 排除正在结算参与者的接口。
- 玩家只付自己的合金丝；NPC只付自己的技能能量。无权使用 NPC 私物；也不能从 NPC 的能量扣到主角上。未被存储且缺可靠原生初态的资源不可凭空初始化。
- `ExploreApproach.CooperationProjectID` 为新增可选门槛。Story 只在同分支/同实例对应工作处于 `worked` 时给 assisted_slow 的可信 capability；纯规则仍检查 clue、位置、互斥和风险。
- 现场方法成功提交时，Realm 变化与 `used` 标记原子写入；请求重试读原结果。即使另一次行动使原目标不再可行，也不将工作产物退成可跨实例使用的通用增益。
- 不允许普通 discovery、字符串 promise 或模型声称“已经共同研究”绕过 work。隐藏作者信息不进入共享或方法投影。

### 6.4 版本与文件职责

三处新场地增加方法，定义版本由1.0升为1.1；古修洞府不动。不静默改变旧实例定义含义；本轮不迁移 ITER2 隔离测试局，不为中间开发格式造第二套长期兼容引擎。

|范围|职责|
|---|---|
|`internal/character` 中独立 cooperation 类型/校验（若适合）|Matter 的受控结构、阶段与来源约束；不执行模型或持久化|
|`internal/interactive/story_cooperation*.go`|三个固定项目、实际可见性/同意、双角色原子工作、报告及重放；源角色与成本 adapters|
|现有角色交流/人物事实提交链|验证本人回应与明确共享，生成专用 Cooperation 候选；普通 Matter 不自动升级为资格|
|`internal/interactive/story_realm_explore.go` 邻近独立消费者|由真实工作供给 capability，现场使用时消费；不在公开视图透出任意资格注入口|
|`internal/exploration/explore_*`|三个 assisted_slow 定义与可选项目门槛、1.1版本及验证/克隆；不理解 NPC 存储|
|正式 turn/world 与 interval pass|同回合有序提案、只有一次600秒、NPC忙碌排除、回放与分支|

UI用“可以一起核对什么/我需要做什么/对方能做什么”自然文字；可点入主行动草稿，不直接结算、不覆盖非空草稿，不制造一列每日待办。始终显示独行替代。未认识对应人物时不泄露作者 SourceKey、隐藏身份或其完整能力，只在玩家已知人物投影中给具体伙伴；方法资格的公开投影与正式提交共用同一谓词，不能因为 assisted_slow 本身没有追加物品 Costs 就无条件开放。

## 7. 五组主动风险反例与验收终点

|风险|必须主动验证的反例|合格结果|
|---|---|---|
|**伪协作或人物全知**|高好感但对方不在场；同回合凭空出场/授技；普通Promise伪装方案；NPC只收一句概述却知道完整侧区|均不产生工作资格；共享严格限于玩家明确的已知线索，NPC后来结果只在真实报告后知晓|
|**所有权/原子结算**|星海玩家无丝但NPC有丝；NPC能量5而需6；过期head；同时另一耗时行动；NPC间隔自动恢复抵销6能量|不挪用、不部分扣费；双方成本和600秒一次提交；参与者不在同区间自动练功/恢复|
|**最优日常与无限方案**|重复问同件事10次；改CommandID；退出重进；在另一实例或工作前的平行分支偷用未来结果；重放报告刷亲密|无新资源/额外方法/重复好感；一次方案准确消费，拒绝重复但保留原结果；不是按日刷新|
|**文字成本和自由被流程吞掉**|玩家拒绝分享、对方拒绝、已具专长、只想取部分退出；方案完成后改变主意|保留普通/专长/强行/退出；不强制打完三阶段，不写十遍长叙述；每次仅给新分工/新发现/新后果|
|**AI长期漂移或假完整**|冷重开、工作前后分支、不同世界同名NPC、NPC假称参加了现场；只跑夹具就称自然AI通关|来源、成本、阶段和知情范围一致；不跨世界、不串平行分支未来；合法检查点继承见第9节；规则模拟与自然模型边界分开|

本轮结束须具备：

1. 三世界从真实可达地点亲查场地、见到符合来源的NPC、共事、回到现场使用方案的规则链；星海清楚证明NPC未从l01传送到l05。
2. 一条拒绝/不分享后普通独行成功链；一条已具专长玩家更直接行动链；合作不能成为强制关卡。
3. 三种分工/成本准确；至少一次双方资源不足反例，以及实际工作期间不重复成长/恢复。
4. 已同意但未工作不能开方法；已工作后一次使用与幂等；退出/重进/分支/冷重开不刷新；同一实例互斥策略仍成立。
5. 不同真实处置后报告不同事实，对方未被提前泄露结果；报告无重复物资或亲密奖励。
6. 真组件窄/宽、深/浅、中/英查看，费用、拒绝理由、独行替代、已用/报告状态可理解；主输入与非空草稿不被覆盖。

以上完成即收束，不在本轮追加全世界势力模拟、常驻战斗队伍、天赋树或新的重复活动。没有授权模型端点时，清楚保留自然输入到动作映射、NPC自主表达和长期真人耐玩感未验，不将规则链或合成UI说成真实AI试玩。

## 8. 对长期耐玩的承诺尺度

这仍是有限首片，不宣称三项合作能撑起无限内容。它新增的是可靠的“关系参与解决问题”的消费者：真实经历可以改变向谁求助、愿意分享什么、自己保留哪些能力以及后来怎样相处。以后扩展应增加不同问题、利益冲突和可替代分工，而非把同一研判换三个名字、追加一根声望条，或让玩家为进入玩法先劳动120天。

## 9. 最终实现澄清与审阅范围

本节由实施统筹依据最终源码和正式测试补充，澄清前文“不跨分支”的范围，不改变冻结的生产机制。

- **受信 fork 继承检查点之前的事实。** 该时点已经 agreed / worked / used / reported 的协作状态如实际库存一样继承到新分支，只重绑定当前分支作用域；原 ConsentExchangeID、WorkSourceRef、UsedBy 和报告来源不改写。已经付费的工作不要求再付一次。
- **不能从未来取结果。** 工作前创建的分支不取得父分支后来才完成的方案；平行分支后来新增的同意、工作、使用和报告不互相渗透。已使用后的检查点不会把方案恢复为可用；子分支使用不会消耗主分支自己的检查点状态。
- 已同意但尚未工作时 fork，可引用被可信投影继承的本人真实历史Exchange，不能因Exchange原始BranchID不同就强迫重新询问，也不能接受任意外部来源。
- 正式回归：`internal/interactive/story_cooperation_flow_test.go` 中 `TestCooperationFlowForkInheritsOnlyCheckpointPlanAndUsesIndependently` 和 `TestCooperationFlowAgreedForkUsesAncestorConsentWithoutReasking`；四分支冷重开、一次费用及来源不改写见 `handoff/evidence/iter3/cooperation-flow/REPORT.md` 与 `final-test.log`。

ULTRA独立源码复核指出并促成了真实NPC健康/战斗共同门槛、先问后分享复用意愿、撤回后重新绑定同意、already_worked不抹历史、共享线索实文及反事实收益对照。最终自动验证由实施线完成，不能把设计审阅冒充自然AI试玩或设计者执行了全部整合测试。

用户最新决定：自然游戏模型由下载后本地自测，本轮云端不以此阻断交付，但实际未测试的自由语言映射、自然人物动机、长局耐玩与节奏仍明确保留；没有每日任务、现实等待或常驻队伍承诺。
