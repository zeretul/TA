## Linux 云端准备与启动

依赖版本以包内文件为准：根和 agent/go.mod 当前均要求 Go 1.26.6；前端为 Node.js 22、pnpm 11.15.1（与项目 CI 一致）。工具链和依赖需在云端安装，不复用 Windows 目录链接。建议使用支持 UTF-8 的环境。

从解压后的项目根目录执行：

```bash
sha256sum -c SOURCE-MANIFEST.sha256
go mod download
(cd agent && go mod download)
pnpm --dir web install --frozen-lockfile
```

没有个人模型配置。进入系统设置重新配置云端可访问的模型服务；本机的 127.0.0.1 代理地址不能直接拿到云端使用。不要把模型密钥写回源码。

分别在两个前台终端启动；端口占用时同时调整前后端的 TA_BACKEND_PORT：

```bash
# 终端一：后端
TA_DIR="$PWD/.ta-cloud-data" TA_BACKEND_PORT=8080 go run ./cmd/ta --dev-mode --no-open
```

```bash
# 终端二：前端。由云端平台转发 5173，后端走 Vite 代理。
TA_BACKEND_PORT=8080 pnpm --dir web dev --host 0.0.0.0 --port 5173
```

若 DOT 的预览域名受 Vite host 检查限制，按实际平台域名配置允许列表；不要直接关闭访问检查。后端不必为前端预览直接公开。

根目录不含预编译 dist。开发模式无需内嵌前端；完整构建运行 `bash scripts/build.sh`，该脚本会构建前端、准备嵌入资源、编译主程序和更新器、整理工具/资源。需要依赖下载网络。`build-editions.ps1` 是本机 Windows 维护入口，依赖被排除的本机工具链，Linux 不直接调用它。

## 验证与交付边界

本次仅做源码导出和文件验收，没有改变游戏程序，没有在 DOT/Linux 上重新构建或运行游戏。之前的 Windows 验收不等于云端已通过。云端完成首次配置后按影响运行：

```bash
go test ./...
go vet ./...
(cd agent && go test ./... && go vet ./...)
pnpm --dir web check:i18n
pnpm --dir web test:unit
pnpm --dir web build
```
