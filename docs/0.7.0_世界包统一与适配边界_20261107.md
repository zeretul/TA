# 0.7.0 世界包统一与适配边界（2026-11-07）

## 本轮最新决定

按用户本轮补充，目标是“通用底座＋世界包＋AI 推理”，不是给每个世界、每个特殊机制制造一个程序。世界书不仅是背景介绍，也应写清世界怎样运转。新世界可以只有一种核心机制，不必凑齐战斗、等级、制作、职业或经营模块。

本轮保留并隔离已经存在的正式结算，不重新发明玩法；新增的包内条件只是迁出旧代码中已有的条件，不作为今后逐项扩充专用规则引擎的路线。

## 如何适配新世界

| 内容 | 放在哪里 | 底座承担什么 |
| --- | --- | --- |
| 世界的自然规律、社会习惯、特殊机制、适用条件与相互影响 | 世界书的独立主题条目 | 按所属世界和当前事实取用，交给 AI 推理 |
| 人物态度、线索解释、承诺是否履行、特殊现象的具体表现 | AI 结合世界规则与本局事实推演 | 使用已有状态、人物记录和本局资料保存正式结果 |
| 已有的物品转移、资源消耗、时间经过、战斗与修炼结算 | 包选择已有能力，并提供自己的数据 | 校验输入、保证资源一致、原子提交、重试不重复支付、分支与重开一致 |
| 新机制需要表达的状态 | 优先复用已有字段、对象与本局资料 | 只有现有表达确实承接不了必要结果时，才补最小通用持久化能力 |
| 尚无实现的精确计算、外部联动或独立交互 | 明确能力缺口 | 不因世界书写了名字就宣称已经实现；不按世界名称猜测能力 |

判断顺序：先把规则写清 → 看 AI 能否据现有事实推演 → 看已有提交能力能否保存结果 → 只有确认的缺口才补程序。不能反过来先建设一套系统，再要求每个世界按它的形状填表。

世界规则要说明“何时发生、付出什么、什么会阻止、当事人能观察到什么、结果如何延续”。规则之间冲突时说明适用条件，避免既把所有传闻当真，也把一切不确定性都写成硬编码判定。玩家正文仍是自然叙述，工程字段和实现边界不放进人物对白。

## 本批已经落实的边界

- 四包都持有自己的地点、路线、任务、探索、公共事件及既有条件；创建故事时冻结，查询、正式提交、回放、分支和展示共用本局来源。
- 删除程序内的世界版本白名单。新增包或内容版本不需要在代码中登记名称；缺少本局目录时拒绝借用其他世界。
- 凡人的既有阶段参数、修炼、寿元、天赋、目录、市场等数据进入包。计算器保留既有受支持的效果与类型，不声称可运行任意新公式。程序中的参考模板只用于明确选择模板时复制初始数据和回归对照，不是四个绑定世界运行时的共享当前目录。
- 明确空的物品、技能、功法、配方、生成模板与世界目录保持为空。模型工具不能借全局模板补回被作者移除的内容。
- 修复同名自定义包另存时内部归属未同步的问题。两个同名世界是两份独立作者资源。
- 世界草稿提示词不再禁止“写规则”，改为组织自然语言的世界规律；重写文案时保留已确认的包数据。没有新增脚本解释器、专用誓约系统或另一套状态提交入口。

## 凡人资料整理

保留 107 条原有人物资料，新增 19 条中英文公共资料，共 142 条：修行与突破、灵根资质、功法术法、寿元休养、低阶经济、传讯，宗门世家，坊市山门，散修/弟子/强势出身的日常，以及凡俗社会与亲缘。

后期资料区分公开常识与具体当地见闻。“通往灵界的远行”不再常驻；具体跨界准备按已提交的阶段与地点取用，各灵界地方资料按所在地取用。搜索、名称读取、ID 读取和常驻上下文共用同一过滤。作者在资料库查看自己的原始世界书不受此限制。

整理了重复价格、行程、制作数字与直接公布宝物/解法的正文。正式数值读取本局规则，调查结果通过实际经历取得。新增内容属于本游戏世界设定补齐，未宣称完成原著逐章考据，也未重写人物私有关系。

## 验收边界

独立的“誓约岛/记忆房间”用例只提供模拟 AI 已作出的结果，再通过现有 StateUpdates 验证持久化、冷重开、分支和跨世界隔离；没有为这些世界新增执行程序。这证明底座能承接此类结果，不代表真实模型已经在各种陌生机制上推理正确。

两套不同修仙参数的真实 Store 用例验证属性、修炼、价格和商户资金在冷重开后仍独立；四包既有玩法由原生集成测试回归。最终测试、程序哈希、页面截图和三版安装证据见本批交付记录与 `.ta-dev/070-world-unification/`。验收完成前不把候选写成已交付。

## 本轮保持的范围

只操作主开发目录与获准同步的三套本地冒险版本。历史推演工作树、进程、数据、共享依赖和 Git 历史不在范围内。用户不要求兼容试玩旧档；正式目录目前未发现活动冒险 journal，因此不需要清空私人数据。配置、归档和旧备份保留。
