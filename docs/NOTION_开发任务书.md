# NOTION 云端开发任务书

日期：2026-11-10。这份文件是给云端开发方（NOTION）的任务书。**请从头读完再动手**，尤其是"硬性边界"一节——那里的约束来自项目长期约定，违反会被要求返工。

## 你的任务

在 Text Adventure（下称 TA）0.7.0 源码上，为**斗破苍穹、哈利波特、诡秘之主**三个世界准备适配能力，并按登记顺序验证哪些能用现有能力承接、哪些确需补通用代码。

这是**分析加最小验证**任务，不是"把三个世界做完"。三个世界包本身不在本次范围。

## 第一步：拿代码

仓库：`https://github.com/zeretul/TA`（私有，需要授权）

```bash
git clone https://github.com/zeretul/TA.git
cd TA
```

**不要克隆整个仓库后就地改。** 按下面方式挑你需要的东西：

- **代码全都要**：根 module + `agent/` 子 module 都在仓库里，两者都是独立 Go module，必须分别构建。
- **文档挑着读**：`docs/` 有 150+ 份文件，其中**大部分是历史交付记录**，路径和结论都过期了。先读 `docs/文档地图_当前设计与历史记录.md`，它标明了哪些是当前设计、哪些只是历史现场记录。按错文档做决策会重复造轮子或推翻已定方案。
- **前端产物要自己生成**：仓库不含 `web/dist` 和 `internal/webfs/dist`，跑 `pnpm --dir web build` 生成。

## 第二步：按顺序读

1. `AGENTS.md` —— 项目长期不变量，**优先级最高**。这里写的规则不能违反。
2. `PROJECT.md` —— 产品与架构。
3. `progress.md` —— 当前交付状态、已做了什么、证据在哪。
4. `docs/文档地图_当前设计与历史记录.md` —— 分辨哪些文档可信。
5. `docs/DOT_0.7.0_云端开发接手.md` —— 环境准备与启动命令。
6. `docs/三世界机制与底座适配分析_20261108.md` —— **你的任务书正文**，WP-01 到 WP-07 在这里。
7. `docs/经营底座与剧本包_核心规则.md` —— 若涉及经营玩法。

读到 `docs/` 里带日期的文件（`0.6.x_*`、`0.7.0_*_2026MMDD.md`、`TA_*_2026MMDD.md`）时，记住它们只描述**那一天**的状态。里面的本机路径（`E:/游戏/游戏开发/...`、`C:/Users/...`）是历史记录，不要按它们找文件。

## 第三步：做什么

按 WP 编号顺序推进，**不能跳步**。每一步的完成标准在 `docs/三世界机制与底座适配分析_20261108.md` 的表格里，这里只说明重点：

### WP-01 划定范围

为三个世界各确定：原作版本、年代、区域、可玩阶段、角色起点。把**原作规则、游戏化约定、未核实设定**三样分开写。

哈利波特的自由时间旅行、诡秘之主的无限制高序列因果改写**明确列在范围外**，不要实现。

### WP-02 世界书与状态映射

为每个世界整理机制清单，每条必须说明：前提、例外、代价、失败后果、需要读取/保存的事实、规则如何取用。

重点映射：
- **斗破**：境界/星级、功法、异火持有与炼化、炼药
- **哈利波特**：已学咒语、魔杖持有/忠诚、真实身份/伪装、效果期限
- **诡秘**：途径/序列、扮演依据、晋升条件、污染来源、封印物代价、知情事实

**先复用现有对象/列表与正式提交。拒绝只写正文不落状态的实现。**

### WP-03 条件知情

复现当前知情门槛的缺口，提出按"本局授权 / 已获线索 / 世界自定义阶段"过滤资料的最小方案。要区分三种知识：裁判知道什么、主角知道什么、各 NPC 知道什么。

**只实现复现证明必要的通用补强。** 不要顺手重做整个知情系统。

### WP-04 持续效果

用复方汤剂和封印物代价验证现有持续效果记录。覆盖：开始、期限、解除、跨期等待、周期代价、多效果并存、失败重试、重开。

**用现有正式时钟与提交，不新增第二套时钟。**

### WP-05 成长结构边界

验证斗破境界、诡秘序列能否用通用状态表达。明确回答：现有数值模块能复用到哪里、是否真的需要固定计算。

**不要换名套用炼气/筑基结构，也不要用普通经验升级冒充。**

### WP-06 最小验证样例

三个世界**分别**做最小样例，执行反例清单：异火未炼化、缺材料、伪装知情差异、结界限制、缺晋升事实、秘密越权、封印物跨期。另加取消/重试、冷重开、分支隔离。

**必须保留真实模型输入输出、正式状态和重开证据。AI 正文写得对但实际状态错 = 失败。**

### WP-07 汇总与回归

汇总哪些问题靠世界书修正、哪些靠配置、哪些确需通用代码。实现后的代码改动按影响做回归，复核四个已有世界（凡人修仙、武侠、星海、西幻）与自定义通用世界。

## 硬性边界

这些是项目长期约定，不是建议。违反会被要求返工。

### 架构

- `agent/` 是独立的 Native Agent Runtime，**不感知外部 runtime**。不要通过给它注入外部 runtime 来实现切换。
- 多 runtime 能力聚合在 `internal/agents/runtime`，不新增 Go module。
- 游戏**不支持 Goal**。UI、API、执行层都不得开启。
- 不引入世界名分支（不要写 `if world == "斗破"`）。专有规则放在世界包内容里，不写进代码。

### 不要做的

- 三个专用战斗/升级/污染引擎
- 任意规则脚本引擎
- 自由时间旅行
- 没有实际需求的中途顶层 schema 扩展
- 每日任务、签到、重复刷次数、现实等待
- 把普通生活、关系、组织、制作做成合同、审批、清单

### 数据与配置

- 不新增第二套时钟、第二套 Todo、第二套 Goal。
- 每个注入片段必须有明确来源、用途、容量上限，并说明超限处理。
- 用户内容的自动迁移/重命名/删除必须有回滚路径或备份。
- `.denova` 相关：受管 Project 以稳定 `ProjectID` 为身份；路径持久化为 `/` 分隔的相对路径；宿主绝对路径不得写入 Registry/Session/metadata。

### 语言

- 模型可见内容（提示词、上下文片段、工具说明、schema 自然语言）用**中文**，不重复注入双语。
- 代码标识、JSON 字段、协议枚举、模型 ID 保留原样。
- 用户可见交互、错误、空状态需要**独立的中英文资源**，按当前语言单语展示。
- 注释、日志、内部错误、终端输出用**英文**。

### 交付

- **不要发布、不要打 Release、不要把仓库转公开。** 这是私有开发仓库。
- 不附带密钥、存档、依赖目录、`dev-data`、`.ta-game`、`config.toml`。
- 不因拿到源码就自动同步到任何安装目录。

## 验证要求

先安装依赖：

```bash
go mod download
(cd agent && go mod download)
pnpm --dir web install --frozen-lockfile
```

按影响范围运行，结果如实记录：

```bash
go test ./...
go vet ./...
(cd agent && go test ./... && go vet ./...)
pnpm --dir web check:i18n
pnpm --dir web test:unit
pnpm --dir web build
```

注意：
- 根 module 的 `internal/app` 包测试**很慢**（数百秒级）。如果看到 `panic: test timed out` 且耗时正好约 600 秒，那是 go test 默认超时，不是代码缺陷。用 `-timeout 1800s` 重跑。
- 涉及 UI 必须打开页面验证，检查窄屏、宽屏、长文本、空数据、明暗两种主题。
- 涉及模型要记录**实际模型调用结果**。未配置模型不能算通过。
- 测试用独立数据目录与端口，不复用真实数据。

## 交付与合并

你的改动最终要合回本地开发库，所以：

- **一个逻辑改动一个提交**，commit message 用**英文**，说明为什么改而不是改了什么。
- 不要 `git reset`、不要强制推送、不要改写历史。
- 不要用整个包覆盖式提交（会冲掉本地其他改动）。按文件、按稳定 ID 合并。
- 交付时提供：源码差异、实际验证结果、**未验证项和原因**。
- 状态分开写清楚：`规则已整理` / `样例已验证` / `必要能力已实现`。**不能统一写成"适配全部完成"。**
