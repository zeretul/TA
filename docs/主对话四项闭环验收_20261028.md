## 为什么此前反复停在“部分完成”

1. **源码基线混用。** 根目录 HEAD 是 `4f39a51c1`，而 0.6.5 的等待与信件修复在另一工作树的 `ddf8b5676`。Luna 从旧根目录构建候选，旧问题重新出现。本轮按文件做三方合并，保留双方修改；16 个 Go 文件的原字节备份和合并记录在 `.ta-dev/parent-closeout/v065-merge/`。
2. **收件和书面回信混为同一步。** 原信已经收件结清后，后续正式书面回信被校验拒绝。本轮允许同一收件人对已送达的原信追加一次书面回信，仍拒绝重复、错收件人和放弃的信件。
3. **资料不等于数值角色。** 首次登场的模型可能只提交 profile。本轮让首次灵兽也能读到可用功法；并在提交时拒绝“已经交战但对手没有可结算 Actor”的不完整登记，允许模型在同一模块重试时补建。没有凭名字自动发修为或造敌人。
4. **验证脚本也有误判。** NPC 的私有境界被 API 隐藏，不能据此判断存档没境界；实际检查原始隔离日志可见 `qi_1`。浏览器的语言头也属于命令身份，重试必须复用；对不上造成的 409 属于夹具问题。本轮没有放宽产品校验。
