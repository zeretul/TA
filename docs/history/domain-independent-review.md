# 历史领域独立复核

本轮对 `internal/history` 做了独立复核，审查者未编写该领域实现。范围是首个历史推演切片的账目、项目、规范日志、重复命令、并发开局与回档记录。没有扩展到未迁入的战争、外交等机制。

## 发现并修复

1. **分期收益被取整吞掉。** 初始练兵值25，同样10000两支出：一季完成得到27，分四季完成仍是25。原因是每季对小额支出分别向下取整。领域现按累计支出跨越的阈值结算增量；独立新档复核，一季和四季均得到27。赈济的粮食、流民和民心增量也按累计阈值处理。
2. **一个坏档阻断全部历史存档。** 独立探针中三份正常存档加一份损坏存档，原目录列表返回整体错误。现目录仍列出三份健康档和一份明确不可读标记。HTTP回归确认健康档可打开、新局可创建、坏档原字节不变；没有静默覆盖或删除坏档。
3. **AI 执行缘由没有进入正式奏报事实。** 原来项目延误/效率建议中的具体原因在预结算后丢失，奏报只能看到通用状态代码。现 `applied_adjustments` 保存实际采用的原因；暂停、条件等待、缺款或无执行能力的项目不会冒称采用。冷读测试确认真实延误原因仍在，缺款项目继续按缺款解释。应用提示词使用这份已保存来源，并以实际逐项结果判定进度。

回档附属记录也已核对：旧检查账目保留原文，带 revision 与 discarded 标记，不再冒充当前账目；原始日志与恢复点没有被回档操作删掉。并发开局、重复提交、坏首记录、删除缓存索引后的冷重放等由领域17项定向测试覆盖；领域静态检查通过。

本复核使用独立临时档，没有更改正式游戏或私人存档。独立探针源码和临时存档原位于 `.ta-dev/history-slice/domain-review`；本页保留复核结果后，已核对路径并清理该临时目录。真正的模型试玩与浏览器结果由交付记录单独说明，不能由这些规则测试替代。
