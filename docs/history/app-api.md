# 历史推演：应用与 API 边界

本页描述隔离工作树中的首个可玩切片，不表示已装入正式 0.7.0，也不表示原历史模拟器的全部机制已经迁入。领域事实与存档结构见 `internal/history` 及同目录领域说明。

## 独立入口与模型

`POST /api/history/bootstrap` 创建或重新找到数据目录内 `games/history` 对应的受管 General Project。它有稳定 ProjectID 和独立 Project Store，不切换当前冒险的 Book，不读写冒险 Story。实际历史存档保存在该 Project Store 的 `history/<campaign>/journal.jsonl`。

模型使用这个独立项目的有效配置，继承现有全局模型设置；采用现有 `interactive_story` 模型用途，不增加另一套密钥文件。历史提示词单独组成，不注入冒险自定义叙事、世界隐情、工具或技能。本批没有修改现有模型配置文件、modelio 或本地私人定制。

## 请求约定

bootstrap 返回 `project_id`、`scenarios`、`campaigns`。后续接口前缀为 `/api/projects/{project_id}/history/campaigns`：

| 请求 | 作用 |
| --- | --- |
| GET / | 列出历史存档 |
| POST / | 用 name、command_id 新建存档 |
| GET /{id} | 读取当前状态与完整记录 |
| POST /{id}/chat | minister_ids、message：单人召见或多人廷议 |
| POST /{id}/prepare-edict | text：AI 拟办；可用 source_chat_id 绑定选定的有效议事，返回 plan 与逐项校验结果，不写入事实 |
| POST /{id}/edict | 玩家确认 plan 后正式颁行 |
| POST /{id}/advance | AI 提议有限执行变化，规则预结算，AI 撰写奏报，再整体提交 |
| POST /{id}/checkpoints | label：创建恢复点 |
| POST /{id}/restore | checkpoint_id：恢复核心状态，原始历史仍保留 |
| POST /{id}/inspect | target：treasury、regions、project ID 或 report ID |
| POST /{id}/cancel | command_id：取消该局正在处理的明确请求 |

除读取、新建和取消外，请求均携带 `command_id`、`expected_revision`；AI 请求另接受 `locale`，产品语言请求头优先。成功变更返回 Receipt，其中 state 是最新完整状态。新建与其他正式操作均有持久去重凭据；失败或未完成的拟办没有变成正式诏令。错误使用 `api.history.*` 编码和独立中英文正文。

客户端取消时应调用 cancel，再中止浏览器等待并重新读取状态。浏览器断开连接本身不能保证底层模型调用已取消；提交与取消竞态以重新读取的正式状态为准。

## AI、事实与记忆

- 由议事拟诏时，服务端按 source_chat_id 只读取同局、当前分支有效的那场原始讨论，连同大臣方案、玩家的话和时间交给拟诏模型；不再只复制玩家的提问。模型同时看到最新钱粮事实，建议只作为待确认方案，不能冒充已执行结果。无关私谈不进入上下文，关键参数仍不清楚的事项继续列为待澄清。玩家确认后，正式诏令保留来源ID，可沿工程与季度结果追溯；直接输入诏令的原流程保持不变。
- 诏令按整段语义拆分，支持赈济、练兵、地方工事及暂停、恢复、追加经费、换负责人。执行条件与前置项目保留；未实现机制和关键参数不明的意图明确列为未执行，不靠换措辞伪装支持。
- 所有结构化模型调用使用现有提供方 JSON 对象模式。若返回仍不符合协议，最多用同一份原始事实请 AI 修复一次格式；不会从普通正文猜出钱粮动作，也不提取或保存模型思考内容。第二次仍不合法就拒绝提交，用户可重试。
- 季度 AI 仅可在领域允许范围内建议效率、延误、地区灾情小幅变化。钱粮、项目状态、进度和时钟由领域核验。奏报只接收预结算结果；模型失败、取消或保存时版本变化，都不会留下半个季度。
- 大臣还能看到仅含身份与职务的公开可用名册，以及当前已经实现的政务种类；其他大臣的性格私情、能力数值和私谈不会通过名册注入。要求当前可执行方案时，规则要求使用现有负责人、总钱粮和计划季度数，避免把尚未实现的分批拨款、购粮转售、任命新官混成主要方案；未给出的百分比不自行换算。
- 每位大臣获得自己的最新已知事实、负责项目、相关原话和近期对话。旧谈话中的数字标为历史，不作为当前账面事实。完整原话留在存档，不因上下文容量自动删除。
- 私聊只检索本人在场的记录。廷议只注入当前全体与会者都曾在场的旧廷议；单独召见和另一批人的会议不会自动流入新廷议。为保守限制泄密，此切片中私人承诺需在私人召见中回忆，或由玩家在本次会议明确告知。
- 同一局同时只处理一项应用操作。相同请求的并发重试等待同一结果；已提交请求重试直接读取持久凭据，不再次调用模型或重复扣款。另一个程序写入存档后，旧模型结果不能覆盖新版本。

## 本批实际检查

Windows 原生 Go 定向检查：15 项应用行为测试、3 项 HTTP 链路测试通过。覆盖独立项目和设置、召见重试、私聊与不同与会者隔离、拟诏不执行、未知意图保留、AI 奏报失败、取消、并发版本变化、季度预结算后提交、存档恢复、双语错误、严格请求解析、坏档不阻断其他存档及新开局、模型JSON输出模式、一次格式修复与修复失败不提交、议事建议进入拟诏、无关私谈隔离及废弃来源在调用模型前拒绝、公开名册投影不泄露其他大臣私密字段且不改写玩家原话。真实模型与浏览器检查由本批根任务另行记录，不把这些测试替代真实试玩。

实际浏览器曾遇到一次模型正常结束但最终内容不符合JSON对象协议，接口正确拒绝且没有写入半条对话。诊断记录只有调用元数据，未捕获原始正文，因此没有将其臆断为某一种具体回复。对应修复先由3项新回归复现失败，再确认通过；最终本机模型复验见本批交付记录。
