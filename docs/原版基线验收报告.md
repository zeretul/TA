## 二、关于「和安装包是不是一模一样」

**结论：不能声称逐字节一致，本报告也不这样声称。**

理由：安装目录里那个 `denova.exe` 的编译记录显示 `vcs.modified=true`，也就是**它是从一个有未提交改动的源码树编译出来的**。因此：

- 上游仓库在 `9c2e922f` 处的公开源码，与安装包里那个二进制，**没有被证实是同一份**；
- 本包以**公开源码的固定提交**为基线，这是一个**可复现、可审计**的起点；
- 本包不声称与原版安装包行为逐字节等价，只声称**基线来自官方公开源码的指定提交**。

如果将来需要更严格的等价性结论，需要另行取得安装包对应的源码快照，本包不做这个推断。

## 三、原版基线运行验证（阶段 A）

**目的**：在动手改任何东西之前，先证明「未修改的官方源码能在本机跑起来，并且真实模型链路通」。

**做法**：

- 使用**可移植 Go 工具链**（`%LOCALAPPDATA%\denova-toolchain\go`，Go 1.27.0）编译基线源码；
- 前端用 `corepack pnpm` 构建，产物经 `-tags embedweb` 内嵌进二进制；
- 使用**独立数据根**与**独立端口**运行，不进入你真实的 `.ta-game`；
- 模型走真实网关 `http://127.0.0.1:8317/v1`，模型 `deepseek-v4.1-flash`，网关无需 API Key。

**验收脚本**：`web/scripts/real-model-acceptance.mjs`

**结果：22 / 22 通过。** 覆盖内容：

| 类别 | 覆盖的验收点 |
| --- | --- |
| 创建 | 创建工作区、创建故事线 |
| 真实模型首幕 | 首幕生成、首幕长度达目标量级 |
| 自由推进 | 自由输入推进成功、第二轮正文达目标量级 |
| 游戏入口 | 侧边栏含「游戏」入口、游戏主舞台输入框可见 |
| 历史回看 | 切换回已开局故事线、主舞台显示正文（历史回看） |
| 持久化 | 刷新/重启后正文恢复、重启后回合数一致 |
| 浏览器内推进 | 经原版输入链推进一回合 |
| 分支 | 创建分支、分支列表含新支线、切换分支、新分支继承父回合且可独立推进、主线状态未被分支切换污染 |
| 隔离 | 同工作区新故事独立（无串档）、新建故事后原故事回合未受影响 |
| 前端健康 | 关闭首启引导遮罩、浏览器无未预期报错 |

关键证据（首轮基线运行）：

```
首幕生成（真实模型）        1291 字
自由输入推进成功            第2轮 1794 字
浏览器内经原版输入链推进     2 → 3 回合
新分支继承父回合且可独立推进   分支回合数 3
主线状态未被分支切换污染      主线 3 vs 3
同工作区新故事独立（无串档）   新故事回合数 0
```

> 说明：首幕 1291 字低于本包默认的 2500 字目标。这是**基线原版**在默认参数下的表现，属于「原版能跑通」的证据，不作为质量问题处理。剧本包已经把 `reply_target_chars` 提到 2500，实测开局稳定在 1400–2100 字区间（见下）。

阶段 B（精简游戏入口）改动了前端默认入口与侧边栏默认可见项，因此**重跑了同一套基线验收**，确认原版链路没有被改坏。

**结果：22 / 22 通过**（与阶段 A 一致）。

- 默认入口从「写作」改为「游戏」；
- 侧边栏默认隐藏 `writing` / `agentchat` / `skills` / `agents` / `automations`；

这两项改动**没有**影响故事线的创建、推进、持久化、分支和隔离能力。

## 六、交付入口验收（阶段 D）

`启动.bat` 本身也按「用户真实路径」验证过一遍：**强制重建**（`启动.bat rebuild`）→ 前端构建 → 内嵌 → 编译 → 启动 → 浏览器链路。

**结果：28 / 28 通过**，且运行在 `启动.bat` 自己的数据根 `.denova-game/` 与端口 19720 上。

这次验收特意使用**全新数据根**（不是开发期的 `.denova-baseline`），证明交付入口是自足的：从零开始也能直接开局、推进、回看。

## 七、本报告的边界

- 本报告只对**已运行的验收**负责。上述数字都来自脚本实际输出，脚本产物为 `web/real-model-acceptance-result.json` 与 `web/story-pack-acceptance-result.json`（两者都不入库）。
- **未验收**的能力不在此报告内，也不在交付范围内；这些项目记录在 [集成点与后续迭代.md](集成点与后续迭代.md)，只登记接入位置，不声称已实现。
